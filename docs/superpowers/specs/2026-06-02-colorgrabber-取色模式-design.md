# ColorGrabber 取色模式 设计文档

- 日期：2026-06-02
- 阶段：第一阶段「只取色」模式（未来再加「颜色→浓度」全流程 Activity）
- 技术路线：路线 A —— CameraX + Camera2 互操作（硬件实时预览）+ 软件白归一化测量

## 1. 背景与目标

课题组通过光催化半导体材料降解四环素。降解过程中显色剂与四环素发生显色反应，
颜色深浅与四环素浓度呈线性关系，因此可由颜色反推浓度。目前用商业 App **Color Grab**：
摄像头拍补光后的试管溶液，开白平衡 + 标准色比对。

**本 App 目标**：做一个比 Color Grab 更精准、稳定、专门化的取色工具，输出可靠的颜色数值，
并把数据结构化留存，为后续「颜色→浓度」标定全流程打基础。

**实际拍摄条件**：试管放在**白色背景**前 + **补光**拍摄（画面内天然有一块「白」可作基准）。

### 范围
- ✅ 本期做：取色（实时 + 拍照选区）、手动白平衡、四类色值输出、历史记录、专属相册、CSV 导出。
- ⛔ 本期不做：颜色→浓度标准曲线标定全流程（预留入口，后续独立 Activity，独立 spec）。

## 2. 输出的颜色数值

每次取色输出四类值：
- **RGB**（与 Color Grab 一致，便于对接现有数据）
- **HSV / HSL**
- **Lab / LCh**（CIE 感知均匀色空间，适合比色与色差 ΔE）
- **吸光度 Absorbance**：按 **R/G/B 三通道分别计算** `A = -log10(I / I0)`，需空白参比 I0。

> 比色定量原则：三通道吸光度全部给出，并标注随浓度变化最敏感的「分析通道」（对应最大吸收波长档），
> 未来全流程标定时用该单通道对浓度做线性拟合。总亮度吸光度仅作附加参考，不作主力。

## 3. 整体架构

技术栈：Kotlin + CameraX（预览/拍照）+ Camera2 互操作（手动白平衡 / 锁定曝光对焦）
+ Room（本地数据库）+ MediaStore（专属相册）。
现有工程为 Java 脚手架（`com.example.colorgrabber`，minSdk 24，targetSdk 36），需补 Kotlin 与依赖。

### 界面结构
```
MainActivity
├── 取色界面 CaptureScreen        ← 核心
│     · 相机实时预览 + 中心取色框
│     · 手动白平衡面板（点白校准 / 色温滑条 / RGB增益滑条 / 锁定显示参数）
│     · 锁定曝光对焦
│     · 实时显示 RGB / HSV / Lab / 吸光度
│     · [记录] 存一条 · [拍照] 存原图并转精细选区
│
├── 精细选区界面 PickScreen       ← 拍照后 / 查看原图时
│     · 在静态原图上拖动 / 缩放取色框，可取多点
│     · 同样输出四类色值，可逐点记录
│
└── 历史记录界面 HistoryScreen
      · 列表（缩略图 + 样品名 + 色值）
      · 详情 / 删除 / 编辑标签备注
      · 一键导出 CSV
```

### 模块划分（职责单一、可独立测试）
- **CameraController**：封装 CameraX + Camera2 互操作。对外提供「设白平衡增益 / 锁曝光对焦 / 取一帧」。
- **ColorAnalyzer**：纯 Kotlin 函数库（不依赖 Android）。输入像素 / ROI → 输出 RGB / HSV / Lab / 吸光度。可单元测试。
- **WhiteBalanceEngine**：点白区算增益、色温 ↔ 增益换算、白归一化。纯逻辑，可单元测试。
- **MeasurementRepository**：Room 存取 + CSV 导出 + 相册图片管理。
- **UI 屏幕**：仅负责展示与交互。

## 4. 取色与白平衡数据流

### 实时取色流程
```
相机帧(YUV/RGB)
  → 取中心框 ROI 内所有像素
  → 去除高光/阴影离群点（可选），求平均 RGB
  → WhiteBalanceEngine 用当前增益做归一化
  → ColorAnalyzer 算 RGB / HSV / Lab
  → 若已设参比 I0，算三通道吸光度 A_R / A_G / A_B
  → 实时刷新到屏幕（节流，约每 5~10 帧算一次以省电）
```

### 手动白平衡四件套协作
- **点白背景一键校准**：点预览里白背景一块 → 读该区平均 RGB → 反推使其变纯白(255,255,255)的 R/G/B 增益
  → 同步设到相机（预览实时变）并记录。
- **色温滑条 / RGB 增益滑条微调**：在一键校准基础上手动拉，预览实时反映。
- **锁定**：定下后增益固定（连同锁定的曝光/对焦），界面顶部常显当前色温/增益数值，便于下次复现条件。

### 空白参比 I0（吸光度用）
- 拍一支不加四环素的空白显色管，点「设为参比」→ 存其归一化后 RGB 作 I0。
- 之后每个样品的三通道吸光度都相对它计算。未设参比时吸光度显示「未标定」。

## 5. 数据存储、相册与导出

### Room 实体 `Measurement` 字段
```
id, 时间戳, 样品名, 备注, 降解时间点(可选)
来源(实时/选区), 关联原图URI(可空), 取色框位置(x,y,w,h)
原始平均RGB, 白归一化后RGB
HSV(h,s,v), Lab(L,a,b)
吸光度 A_R / A_G / A_B（无参比则空）
白平衡参数(色温 / RGB增益), 是否为参比(I0)标记
```
> 设计要点：**白平衡参数与原始 RGB 都存**，算法变更后可从原始数据重算，历史数据不作废。

### 专属相册
- 拍照原图通过 MediaStore 存进系统相册 `ColorGrabber/` 文件夹（自带相册 App 可见）。
- 记录存该图 URI，实现「记录 ↔ 相册照片」双向关联；删记录可选是否一并删图。

### CSV 导出
- 历史列表一键导出，表头为上述全部字段，一行一条记录。
- 通过系统分享 / 存 Documents，便于传电脑做曲线拟合。
- 中文表头 + UTF-8 BOM，保证 Excel 打开不乱码。

## 6. 错误处理、权限与兼容

### 权限与兼容
- 相机权限运行时申请；拒绝时给说明并引导去设置。
- 存图：Android 10+ 用 MediaStore（无需存储权限）；minSdk 24 低版本走兼容分支。
- 手动白平衡增益依赖机型 Camera2 支持。**降级策略**：不支持手动增益的设备退回「软件白归一化」（路线 B），
  功能不丢，仅预览不实时变色，界面给提示。

### 边界情况
- ROI 压到白背景/高光过曝 → 提示「区域过曝，请避开高光或降低补光」。
- 未点白校准就测 → 用默认增益并提示「建议先点白背景校准」。
- 未设参比就看吸光度 → 显示「未标定」。

## 7. 测试策略

- **ColorAnalyzer**（RGB→HSV/Lab、吸光度公式）：纯 Kotlin **单元测试**，用已知色值验证（纯红、纯白、标准色卡数值）。
- **WhiteBalanceEngine**（点白算增益、色温↔增益、归一化）：**单元测试**，用构造像素验证。
- **MeasurementRepository + Room**：instrumented 测试验证存取与 CSV 导出格式。
- 相机 / UI 部分：手动验证为主。

## 8. 未来扩展（不在本期）
- 「颜色→浓度」全流程 Activity：用已知浓度样品建标准曲线（分析通道吸光度 vs 浓度线性拟合），
  再对未知样品直接读浓度。复用本期 ColorAnalyzer / WhiteBalanceEngine / Measurement 数据。
